# FetchXML → Web API Mapping

`GET /api/data/v9.2/<entityset>?fetchXml=<url-encoded fetchxml>`. FetchXML is the
richest read dialect (aggregates, multi-level link-entity, late-bound filters).
The CAT skill's detailed mapping tables were never published (referenced files
missing from the repo) — this document is our reconstruction; extend it as
real queries demand.

## Element mapping

| FetchXML | Web API OData equivalent |
|---|---|
| `<entity name="account">` | URL entity set `accounts` |
| `<attribute name="name">` | `$select=name` |
| `<filter>` / `<condition attribute="x" operator="eq" value="1">` | `$filter=x eq 1` |
| `<link-entity name="contact" from="parentcustomerid" to="accountid">` | `$expand=<navigationProperty>($select=...)` |
| `<order attribute="createdon" descending="true">` | `$orderby=createdon desc` |
| `<aggregate>` + `aggregate="count"` | `$apply=groupby(...,aggregate(...))` |
| `page`/`count` attributes | `@odata.nextLink` pagination |
| `distinct="true"` | `SELECT DISTINCT` via `?sql=` |

## Operators quick map

`eq ne gt ge lt le` → same in OData · `like` → `contains(x,'v')` (or SQL LIKE) ·
`in` → `in(x,(1,2,3))` (OData v4.01; fallback: `or` chain) · `null/not-null` →
`eq null` / `ne null` · date operators (`today`, `last-x-days`, …) → compute the
date client-side, then `ge`/`lt`.

## When FetchXML beats OData/SQL

- Multi-level joins (link-entity chains) beyond INNER/LEFT 1-hop SQL
- `aggregate` with grouping over a single entity set (also `$apply`)
- Late-bound / dynamic queries generated by tools (views exported from the maker
  portal are FetchXML)

## Guards (enforced by dv_query.py)

FetchXML is rejected if it does not start with `<fetch` or contains mutating
elements (`<insert>`, `<update>`, `<delete>`, `<upsert>`, `<merge>`). This skill
only ever sends it as a GET parameter — the service-side `<service>`/action
execution forms are out of scope.

## Do NOT silently drop

Aggregates, nested link-entity, and late-bound conditions have no faithful OData
translation — if you can't map a query faithfully, send it as FetchXML instead of
approximating.
